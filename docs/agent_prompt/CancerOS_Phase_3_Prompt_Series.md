# CancerOS Phase 3 — Simulation and Longitudinal Intelligence

Version 1.0 | 23 October 2026 | 16 separate prompts | 15 P0 and 1 optional P1

This series continues Phase 2 and preserves its Muse Spark-oriented structure: a clear role, explicit prerequisites, one concrete outcome, numbered implementation steps, usability behavior, acceptance checks and completion evidence. This is a prompt-structure adaptation, not a benchmark claim. These are prompts for future coding work; no application code, model training or clinical validation is asserted to have been completed by creating this pack.

Run one numbered prompt at a time. Copy that task's fenced text into the coding-agent session with repository access. Retain COS-000 persona, AGENTS.md, adopted baseline decisions and the ledger. Each prompt also embeds the core role/guardrails for a fresh session. Expert perspectives organize self-review when one agent is working; they do not substitute for real scientific review or require spawning agents.

Canonical invariants:

- State context OBSERVED/SYNTHETIC is separate from item provenance, technical QC, scientific review, availability and publication. The observed baseline is a shared reference; every generated descendant remains SYNTHETIC_GENERATED, including derived measurements/meshes/trends. Branch-aware mixed-baseline views retain item-level origin.
- A complete demonstration branch has baseline plus at least three generated follow-ups. These are four positions, not four authentic examinations. Source-relative time uses its independent timeline origin; never invent an absolute calendar date.
- Accepted source data and published run/snapshot content are immutable. Reruns/corrections append new versions. Branches stay pinned to the original baseline hash. Workers produce ready outputs; authorized explicit publication exposes a complete validated run.
- Tumor burden and clinical condition are separate model dimensions. They can be configured to interact, but one must not automatically determine the other. Stable size is not stable health; shrinkage does not prove treatment benefit.
- Parameters, distributions and bounds are versioned demonstration assumptions unless supported/reviewed otherwise. No automatic RECIST/CTCAE, molecular resistance, prognosis or dose recommendations. Uncertainty from measurement, simulation parameters and prediction stays distinct.

## Usability and functionality priorities

1. Make the right next action clear: valid defaults, readable scenario/metric labels, exact missing prerequisites, preserved draft inputs and safe retry/cancel/publication actions.
2. Keep origin, units, source time, branch and assumptions visible. Use separate presentation for observed, simulated and forecast points; color alone is insufficient.
3. Keep arithmetic and state fusion deterministic and source-linked. Charts need readable tables, true time spacing, accessible controls and explicit missing gaps. A connecting line is not an extra measurement.
4. Reuse existing screens and components. COS-050 adds the thin simulation workflow; COS-051/052 add timeline/chart integrations; later full UI workstreams retain their scope. Backend tasks still provide actionable typed responses and runnable examples.
5. Fit modest hardware: lazy images, one branch/small bounded batches, CPU tabular generation, reusable meshes and measured resource budgets. Keep neural experimentation optional on the Ryzen 5 3500U/8 GB target; do not assume available GPU/cloud credits.

## Evaluation and release boundaries

COS-050 must map SLRE-T01–T24 and V1–V8 to evidence. SPEC-011's initial regression target is five families × at least ten fixed seeds (at least fifty trajectories) on suitable engineering baselines, plus a repeated full five-family set. Distinguish tabular tests from actual mask/mesh realization; each family needs a complete curated geometry-enabled example for the declared anatomical demonstration. Always count failures. Proposed arithmetic/geometry tolerances remain engineering checks, not clinical error limits.

Keep synthetic suite results separate from authentic longitudinal evaluation. A real baseline and rights/mask review (D01/D03), a genuine repeated-exam case for full authentic temporal demonstration (D02), patient-separated evaluation (D05), deployment/resource evidence (D06) and policy-controlled external inference if used (D04) are still evidence gates. Synthetic visits cannot close the real-follow-up gate. Passing software rules does not prove clinical realism.

COS-055 is P0 for baseline evaluation tooling and abstention behavior. It does not make patient-facing forecasts mandatory: public estimates remain disabled until endpoint/horizon/population evidence and review are recorded. LOCF as a forecasting comparator does not permit observed-state carry-forward. Learned forecasting/interpolation/calibrated uncertainty remain disabled unless their separate gates close. COS-056 cannot delay deterministic timeline, trends, fusion or updates.

## Phase completion evidence

- Working five-family branch generation with independent tumor/clinical profiles, explicit source lineage, baseline preservation and complete-run publication.
- Actual regression/replay results and failure-injection evidence, with geometry realization, units, branch isolation and note-to-structured-value checks.
- Runnable observed and simulated timeline/comparison/fusion/update workflows that do not depend on an LLM; immutable historical membership and coherent latest views.
- Forecast baseline evaluation/abstention evidence, with honest disabled behavior when real validation is unavailable. No superiority claim from synthetic targets or training loss.
- Updated traceability, task ledger and a concise Phase 3 evidence report separating implemented, fixture-verified, real-data-verified, review-pending and blocked scope. Source/model review must be attributed to actual reviewers, not an agent persona.
