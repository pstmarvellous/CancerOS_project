# Definition of Done

COS-007, SPEC-011 and COS-AUD-001. Done means scoped artifacts integrated; applicable
contracts resolved; relevant positive/negative checks actually passed; evidence,
traceability and ledger synchronized; limitations named. Documentation tasks use
consistency/link/schema checks, not irrelevant medical tests. Installed libraries,
startup and mocked fixtures are not scientific validation.

| Level | Required evidence |
| --- | --- |
| Task verification | Its bounded deliverables and applicable checks, source/reference review, real limitations |
| Phase 1 foundation | Locked install; backend/frontend startup/build; real disposable PostgreSQL migrations/integrity; private object round trip; configured queue and persisted harmless job; safe config/auth denial; lint/types/tests/contracts/governance |
| Complete P0 demonstration | D01–D06, real baseline, genuine longitudinal case, five families, grounding, privacy, restore, usability/performance and rehearsed demonstration |
| Optional scientific enablement | Separately reviewed task-specific real-data evaluation, failure/abstention reporting, permissions and compatibility |

Only the first two levels are Phase 1 targets. Missing mandatory Phase 1 integration
evidence means incomplete foundation verification. No blanket skip/continue-on-error
for critical gates. Real-data/deployment gates cannot be satisfied by fake MRI arrays
or mocked identity. Containers and remote model providers are not mandatory locally.

Reference Review Gate for consequential scientific changes: actual academic section
read; pinned working upstream interface or documented absence; empirical scope;
selected adaptation and license/permission checks; meaningful negative tests. Routine
governance/build tasks may mark medical algorithms not applicable with a reason.

Later suites retain SPEC-011 IDs for geometry/orientation, identity/branch isolation,
historical corrections, reproducible simulation, grounded output/export denial,
state-selection races, backup/restore and authentic case review. Engineering tolerances
remain proposed project test rules, not clinical thresholds. D01–D06 remain unverified.

Record command, versions, requirement/test/task IDs, input/commit hash, result
(passed/failed/not_run/blocked/future_phase), safe output artifact and limitations.
Redact raw data, secrets and protected source maps. Frozen tiny engineering fixtures
are deterministic software checks only. Critical privacy/provenance/identity or
unsupported-claim failures block affected publication/release. A deliberately failing
fixture must make the validator fail; skipped is never passed.
