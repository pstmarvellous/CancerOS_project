## Source Learning Record and Three-Source Decision Note

The adopted `PatientPage`/`PatientSummary` contract exposes only
`patient_id`, `display_code` and `data_revision` per case, with no
search/filter/pagination parameters on the patient-list endpoint. SPEC-009
4.1–4.2 display-code search, source/modality/verified-longitudinal filters
and cursor pagination therefore have no server semantics to bind; the task
ships an honest bounded authorized list and records the gap rather than
inventing client-side equivalents. Subtype, side, examination/branch counts
and modality availability are likewise absent from the contract, so the
list defers them to the opened case (COS-074) instead of fabricating
values. Map queries returned no matching nodes, behaviors or references;
no academic text, upstream code or empirical paper is claimed read or
reproduced.

Decision: implement against the real generated contract and a thin
same-origin proxy; keep unsupported discovery semantics visibly absent.
Verification: case-library component tests plus full frontend
lint/typecheck/test/build/contracts; no live project exercised.
Failure fallback: restricted or failed loads show an honest state with a
role-appropriate next action; no counts are derived from inaccessible
records. Map drift is recorded separately; original maps are unchanged.
