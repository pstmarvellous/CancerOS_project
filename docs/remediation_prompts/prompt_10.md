# COS-REC-09 — Independent Product Acceptance and Portfolio Readiness

**Role:** Independent Senior QA Engineer, Product Acceptance Lead and UX Reviewer

**Mission:** Determine whether the recovered CancerOS application is functional, understandable and suitable for demonstrating engineering capability to prospective clients.

Do not accept prior implementation summaries as proof.

Read the original specifications, adopted decisions, COS-REC-00 through COS-REC-08 acceptance evidence and relevant knowledge maps.

## Required independent journeys

### Journey A — First-time visitor

Open CancerOS in a fresh browser.

Without developer instructions:

1. Understand its purpose.
2. Launch the synthetic demonstration.
3. Manipulate the 3D model.
4. Select different hypothetical scenarios.
5. Follow changes across time.
6. Understand the accompanying observations.
7. Access a clearly labeled research explanation.

### Journey B — Research case management

Using an authorized artificial account:

1. Create a research case.
2. Enter an artificial observation.
3. Save and reopen.
4. Correct a value.
5. Inspect the associated chart.
6. Navigate away and back.
7. Verify patient/case isolation.

### Journey C — Imaging

Use eligible data to:

1. Import an imaging study.
2. Associate an appropriate mask.
3. Run required quality checks.
4. Produce deterministic measurements.
5. Display the result in the 3D viewer.

Separate synthetic verification from authentic MRI verification.

### Journey D — Research workflow

Where the baseline is eligible:

1. Select a case.
2. Configure a supported scenario.
3. Execute the actual engine.
4. Inspect job status.
5. View generated states.
6. Compare synchronized measurements and observations.

Do not substitute prepared demo playback for genuine scenario generation.

### Journey E — AI interpretation

1. Select a permitted state.
2. Request a local explanation.
3. Verify numerical grounding.
4. Inspect the supporting evidence.
5. Verify correct result scope.
6. Separately verify live Meta inference if authorized.

## Evidence requirements

Use actual browser automation, genuine application APIs and disposable test data.

Record:

- Each action attempted.
- Expected outcome.
- Actual outcome.
- Screenshot or trace.
- Backend/API evidence where relevant.
- PASS/FAIL/BLOCKED.
- Reproduction steps for defects.

Review desktop and mobile layouts.

Verify authorization boundaries and negative cases.

## Acceptance verdicts

Issue separate decisions for:

- Synthetic demonstration readiness.
- Research-case management readiness.
- Imaging pipeline readiness.
- Simulation workflow readiness.
- AI integration readiness.
- Overall portfolio demonstration readiness.
- Clinical/research release readiness.

Never combine these into a misleading overall "all tests passed" claim.

## Definition of success

CancerOS is portfolio-demo ready only when a first-time non-medical visitor can complete the synthetic demonstration without assistance and the showcased functionality is genuinely working.

Clinical release readiness is a different, stricter decision requiring the relevant scientific and privacy verification.

Do not mark the application complete if the tested user journey requires developer intervention.

Deliver an evidence-backed acceptance report and a short remaining-defect backlog.
